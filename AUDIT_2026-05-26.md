## Findings by entry

### swallowed-exceptions
**real-defect** — `definitions.py:37`

```python
except Exception:
    WIKTIONARY_CACHE[key] = None
    return None
```

swallowed-exceptions cue: `except Exception` returning `None` — the caller cannot distinguish "Wiktionary returned no definition" from "network error" from "JSON parse failure" from "Wiktionary API changed its response format." All four failure modes produce identical behavior: the word is cached as having no Wiktionary definition, permanently (for the process lifetime). A transient network failure poisons the cache for all subsequent lookups of that word.

The `except Exception` catches `requests.ConnectionError`, `requests.Timeout`, `json.JSONDecodeError`, `KeyError`, `TypeError`, and anything else — all routed to the same `None` result. The function returns `None` to signal "no definition found," but that's also the result of a genuine "Wiktionary doesn't have this word" response (HTTP 404). The swallow collapses failure and absence into one signal.

**Pre-existing:** Yes — this code existed before today's session.

## Compound findings

**swallowed-exceptions + hardcoded-config-values at `definitions.py:20,37`:** The Wiktionary fetch uses a hardcoded 2-second timeout AND swallows all exceptions. A timeout produces `requests.Timeout`, which is caught by `except Exception`, cached as `None`, and the word is permanently marked as "no Wiktionary definition" for the rest of the process. If the Wiktionary API is slow (not down, just slow), the 2-second timeout fires, the exception is swallowed, and the fallback chain moves to Webster's 1913 — which may or may not have the word. The compound effect: transient Wiktionary slowness permanently degrades definition quality for affected words.

---

## Suggested fix order

1. **swallowed-exceptions in `definitions.py:37`** — Narrow the `except Exception` to `except (requests.RequestException, ValueError, KeyError)`. Consider not caching `None` on transient network errors (only cache on 404 / empty response). This is the only defect-direct finding.

2. **hardcoded-config-values** — Move `timeout=2.0`, `max_workers=10`, and `n=100` to `config.py` as named constants. This is cosmetic organization, not a behavior change, but makes tuning visible.
