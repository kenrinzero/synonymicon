## Correctness bugs (fixed)

### 1. BNC reported wrong frequencies for nearly every multi-POS word — HIGH
`corpora.py` (`_load_bnc`, last-write-wins).
`bnc_all.al` has one row per *(surface form, POS tag)*. The loader did `BNC_ZIPF[word] = zipf` (plain assignment), so for any word with multiple POS rows only the **last** row survived.
- `run`: 8 rows totaling 22,125 occurrences; stored value used 6,327 (the `vvn` row) → Zipf 4.87 instead of 5.41.
- `work`: rows total 91,354; stored value used 19,297 → Zipf 5.35 instead of 6.03.

The kept value was neither max nor sum — just whichever POS sorted last. Masked because calibration was anchored on `the` (single-POS-dominant), so spot checks looked fine.
**Fix:** all count-based loaders now **aggregate (sum) counts per lowercased word** before computing the Zipf, via a shared `_load_counts` / `_zipf_from_counts` helper. Regression test: `tests/test_corpora.py::TestCorpusAggregation::test_bnc_aggregates_pos_tagged_rows`.

### 2. Leipzig corpora under-counted capitalization variants — MEDIUM
`corpora.py` (`_load_leipzig_*`, `setdefault`).
Leipzig stores `the`/`The`/`THE` as separate rows; `setdefault(word.lower(), …)` kept only the first (largest) and dropped the rest. `we` kept 39,384 of a true 59,789 (~34% lost); `the` kept 976,578 of 1,131,737.
**Fix:** same count-aggregation path. Because aggregating raises the anchor count, the three Leipzig offsets were **recalibrated** so `the` ≈ 7.73 still holds: news `1.74 → 1.6763`, web_com `1.83 → 1.7779`, web_uk `1.76 → 1.6987`. Regression tests: `test_leipzig_aggregates_case_variants`, `test_leipzig_the_anchor_calibrated`. (Other count corpora — Google/Kaggle/Wikipedia/OpenSubtitles/Gutenberg — have no `the` case-dupes, so their anchors are unchanged; aggregation only corrects any non-anchor dupes.)

### 3. fastText silently dropped for any non-lowercase query — MEDIUM
`candidates.py` (`get_fasttext_candidates`).
The function computed `wl = word.lower()` only to filter self-matches but called `most_similar(word, …)` with the raw-case word. The wiki-news vocab is lowercased, so `"Run"` / `"HARD"` raised `KeyError` → caught → `[]`, dropping the entire embedding source with no error.
**Fix:** query with `wl`.

### 4. OOV handling differed between wordfreq and the dict corpora — MEDIUM
`corpora.py` (`get_zipf`) + `candidates.py` (`_score_and_filter`).
Dict-backed corpora return `None` for unknown words (candidate dropped), but `wordfreq` returns `0.0` (verified), which survived and polluted the `absurd` band — so the same query returned different sets under different corpora.
**Fix:** `get_zipf` returns `None` when wordfreq yields `0.0`, unifying OOV handling. Regression test: `test_wordfreq_oov_returns_none`.

### 5. WordNet reader corrupted under concurrent access — HIGH (latent; surfaced by the hermetic-test work)
`definitions.py` (`get_wordnet_gloss`).
NLTK's WordNet reader `seek()`s a shared file handle. `get_definition` runs under `ThreadPoolExecutor(max_workers=10)`; when many words fell through to `get_wordnet_gloss` concurrently, interleaved seeks read garbage → `WordNetError: line '…'`. Online this stayed hidden because Wiktionary answered most words; it would bite production on OOV-heavy queries.
**Fix:** serialize gloss access with a `threading.Lock`. Reproduced (serial clean / concurrent errors) before fixing; the four API tests that broke when the suite went offline now pass.

### 6. Morphological-variant filter missed plural/agent forms for words ending in `e` — LOW
`candidates.py` (`get_morphological_variants`).
The `if/else` was exclusive: e-words got only e-drop forms, so `make` → `{make, maked, making}` and `makes`/`maker` slipped through as undeduplicated inflections of the query.
**Fix:** simple suffixes apply to every word; e-words *additionally* get e-drop forms. Regression test: `test_e_ending_word_includes_plural_and_agent_forms`.

### 7. Definition cache poisoned by transient Wiktionary failures — MEDIUM
`definitions.py` (`get_definition`).
On a network error, `get_definition` cached the fallback result (often `[undefined]`) permanently for the process lifetime — a single 2 s timeout degraded a word's definition forever.
**Fix:** `get_wiktionary_definition` returns a `NETWORK_ERROR` sentinel on `RequestException`; `get_definition` returns the fallback for that request but does **not** cache it, so the word is retried. Regression test: `tests/test_definitions.py::TestDefinitionCachePoisoning`.

### 8b. Three corpora mis-calibrated — `the` at Zipf 13.4 / 13.4 / 8.6 — HIGH (pre-existing; found during verification)
`corpora.py` (`_COUNT_CORPORA` offsets).
Independent of the aggregation bug (these corpora have no `the` case-dupes), the offsets themselves were wrong: `google_1grams` and `kaggle` used `+3.0` (→ `the` = 13.36) and `gutenberg` used `+0.37` (copied from opensubtitles, whose `the` count is ~7× smaller → `the` = 8.60). A Zipf of 13/8.6 for `the` means nearly **every** word in those corpora lands in the `common` band, so tier filtering was effectively broken for three of the eleven corpora. The session notes even recorded the *intended* values (~7.36) while the code shipped the wrong sign/offset.
**Fix:** recalibrated to the `the` ≈ 7.73 anchor — `google_1grams`/`kaggle` → `-2.634`, `gutenberg` → `-0.5`. Verified `the` is now 7.73 across all self-computed corpora (wikipedia 7.77, opensubtitles 7.73, bnc 7.86, subtlex 7.47 left as-is). Regression test: `tests/test_corpora.py::...::test_the_anchor_holds_across_count_corpora`.

### 8. Triple-character filter rejected valid triple-consonant compounds — LOW
`candidates.py` (`_score_and_filter`). `(.)\1{2,}` rejected `wallless`, `crossstitch`, etc. — exactly the rare outliers the tool exists to surface.
**Fix:** loosened to `(.)\1{3,}` (4+ repeats), still catching embedding junk like `loooove`.

### 8c. Trailing-punctuation cleanup only de-duplicated; it didn't sanitize lookup or output — LOW
`candidates.py` (`_score_and_filter`). `cleaned = key.rstrip('-.')` was used only to re-check the morph set; the Zipf lookup and the displayed word both still used the punctuated form (so `walk-` was looked up as `walk-` and shown with the hyphen), and the `len`/alpha filters ran on the raw key.
**Fix:** strip first, then run all filters, the `get_zipf` lookup, and the display on the cleaned form.

## Frontend bugs (fixed)

### 9. `popstate` re-pushed history for the about view — MEDIUM
`static/index.html`. The `popstate` handler called `showAboutView()`, which itself `pushState`s — so navigating Back into an about state pushed a new entry, corrupting the back/forward stack.
**Fix:** `popstate` now renders the about view directly and never pushes.

### 10. Back to the initial/empty state left stale results on screen — MEDIUM
`static/index.html`. The handler only acted on `state.view==="about"` or truthy `state.word`; the null initial entry fell through, leaving the prior query's results/senses/input visible.
**Fix:** added an `else` branch that resets to the empty state.

### 11. Dead validation-style branch — LOW
`static/index.html`. `err.message.includes("single-word")` was always false (no backend error contains that string), so 3-word-phrase errors rendered in the red error style instead of neutral.
**Fix:** the error now carries the HTTP status; `isValidation` = `4xx`.

### 12. Unguarded `results = data.results` — LOW
A 200 response lacking `results` would make `render()` throw and wedge the grid. **Fix:** `data.results || []` (matching the adjacent `senses` guard).

### 13. Accessibility gaps — MEDIUM (cluster)
- Result headwords were mouse-only → now `role="link"` + `tabindex="0"` + Enter/Space keydown (no visual change), and demoted from `<h3>` to `<div>` (results are a list, not document headings).
- Dropdowns → `aria-haspopup`/`aria-expanded` (synced), single consolidated outside-click handler, and **Escape-to-close**.
- Results grid → `aria-live="polite"` + `aria-busy` during load.
- Peek (next-page preview) column → `inert`, so the `aria-hidden` preview is genuinely non-interactive.
- About section headings `<h3>` → `<h2>`; corpus names demoted to non-headings → clean `h1 → h2` outline.

### 14. Band-separator labels inconsistent with the dropdown — MEDIUM
`BAND_DISPLAY` (`~0–10k`, tilded) disagreed with `FREQUENCY_TIERS` (`common`, `10k–30k`, …).
**Fix:** `BAND_DISPLAY` is now derived from `FREQUENCY_TIERS`, so a band reads identically as a control option and as a separator. (The rank-count framing is wordfreq-calibrated — see *Deferred*.)

### 15. `nextBtn` duplicated pagination math — LOW
Recomputed page count independently of `render()`. **Fix:** just `currentPage++; render()` and rely on `render()`'s clamp + `renderNavArrows`.

### 16. Missing `<head>` metadata — LOW
No favicon (404 on `/favicon.ico`), no `<meta description>`, no Open Graph/Twitter tags.
**Fix:** added an inline SVG favicon (no binary asset), `description`, `theme-color`, and OG/Twitter tags.
